# Проверка отладки

## Что делает этот режим

При сборке с `--debug` в проект добавляются блоки записи в список «лог».
Зелёный флаг запускает программу и запись внутри Robbo Scratch, а не отдельный
монитор COM-порта. MCP не получает данные автоматически во время работы.
После запуска нужно вручную сохранить `.sb3`, затем прочитать его через CLI или MCP.

## 1. Проверить установку

Из папки проекта в PowerShell:

```powershell
npm test
node cli.js build examples/robot_square.json projects/square_debug.sb3 --debug
```

Тесты должны завершиться без ошибок, а сборка — создать `.sb3`.
Это проверка сборки, но ещё не проверка работы на настоящем роботе.

## 2. Запустить и сохранить

1. Обеспечьте свободное безопасное место для движения робота. Будьте готовы
   остановить программу и отключить питание моторов.
2. В Robbo Scratch выберите «Файл → Загрузить с компьютера» и откройте
   `projects/square_debug.sb3`.
3. Подключите робота и нажмите зелёный флаг. Наблюдайте за списком «лог» на сцене.
4. После завершения или остановки выберите «Файл → Сохранить на компьютер».
   Сохраните как `projects/square_run.sb3` в папке репозитория.
5. Не перезагружайте исходный проект перед сохранением: так можно потерять лог.

Без устройства некоторые аппаратные блоки могут не выполняться или ожидать ответа.
Такой запуск не является полноценной проверкой работы с роботом.

## 3. Прочитать результат

```powershell
node cli.js log projects/square_run.sb3
Get-ChildItem .\logs\
```

CLI должен вывести строки лога и путь к сохранённой копии в `logs/`.
Статистика датчиков появляется только при наличии соответствующих записей.

В Cursor перезапустите MCP-сервер, затем попросите агента:

> Прочитай projects/square_run.sb3 инструментом robbo_read_log.
> Покажи, какие действия записались, и отдельно укажи, чего нельзя установить из лога.

## 4. Проверить датчик линии

```powershell
node cli.js build examples/robot_line_follower.json projects/lf_debug.sb3 --debug
```

Откройте файл в Robbo Scratch. В этом примере программа после зелёного флага
ждёт кнопку Start на роботе, затем использует Датчик1 и порог 50.
Проверьте соответствие подключённого датчика настройкам устройства.
После короткого безопасного запуска остановите программу и сохраните
`projects/lf_run.sb3`.

```powershell
node cli.js log projects/lf_run.sb3
```

Сопоставьте значения с положением датчика над линией и фоном.
Попросите агента сначала предложить изменение порога и объяснить его по логу.
Проверяйте по одному изменению за запуск; лог сам по себе не доказывает,
что робот физически выполнил команду правильно.

## Ограничения

- Нет автоматического сохранения при красном стопе или завершении программы.
- Нет автоматической отправки лога в MCP: нужен сохранённый файл.
- Запись описывает программные решения, а не подтверждение движения от устройства.
- Показание датчика для записи может быть получено чуть позже проверки условия.
- Повторяющиеся ветки в бесконечных циклах записываются с ограничением частоты;
  список ограничен 5000 строками. Это не полная трассировка каждого шага.
- Исходник `.robbo.json` следует хранить отдельно и изменять именно его,
  а не сгенерированные служебные блоки отладочной сборки.

## Если не получилось

| Симптом | Проверка |
|---|---|
| Нет списка «лог» | Убедитесь, что открыт файл, собранный с `--debug`. |
| Есть старт, но дальше пусто | Проверьте ожидание Start и подключение устройства. |
| CLI сообщает, что лог пуст | Сохраните проект после запуска, не открывая исходный заново. |
| Файл не найден | Проверьте имя и папку: браузер мог сохранить его в «Загрузки». |
| В Cursor нет `robbo_read_log` | Перезапустите сервер и проверьте, что он запускается из обновлённой папки. |

Для разбора ошибки приложите сохранённый после запуска `.sb3`, вывод CLI,
версию Robbo Scratch и описание подключения датчиков.
